# 0011. Block picker previews are committed, derived rasters

**Status:** Accepted
**Date:** 2026-08-26

## Context

Spec 011 US2 makes the Payload block picker usable. Before it, the picker showed 45
identical grey placeholder glyphs in one ungrouped wall, so choosing a block meant
recognising its name or guessing.

Payload's `BlockSelector` renders exactly three things per card: an `admin.group`
heading, an `admin.images.thumbnail` image, and `labels.singular`. The image is the
only part that carries what a block actually looks like, which makes "where do the 45
preview images come from, and when" a real architectural question rather than an
asset-management detail.

The site already has a capture harness that renders every block in isolation
(`npm run seed:showcase` plus the Playwright visual specs), so the images can be
derived rather than drawn. The question is what to do with them afterwards.

## Decision

**Commit the previews as static files under `public/block-previews/`, generated by an
explicit command (`npm run block:thumbnails`) that is never part of a build.**

- Source: `tests/e2e/visual/screenshots/block-previews/<slug>--<variant>.png`, the
  per-block element captures from `tests/e2e/visual/blockPreviews.e2e.spec.ts`.
- Output: `public/block-previews/<slug>.webp`, 480×320 (Payload's documented 3:2
  ratio), WebP q78, letterboxed on the block's own background colour.
- Budget: 400 KB for the committed set. `tests/int/adminMetadata.int.spec.ts` is the
  CI gate; the generator also refuses to finish over budget, but it is a manual
  command and no workflow invokes it, so it gates the author's run and nothing else.
  Measured at 45 blocks: **141 KB**.
- Blocks that cannot be photographed deterministically ship a hand-authored SVG
  wireframe instead, listed in the generator's `HAND_AUTHORED` set.

The 3:2 letterbox is not cosmetic. Payload draws the thumbnail into an
`aspect-ratio: 3/2` box with `object-fit: cover`, so an image of any other shape is
centre-cropped by the browser — a full-page capture arrives as an unreadable strip of
its own middle. Producing 3:2 ourselves is what keeps the block's content visible.

## Rejected alternatives

- **Generate at build time.** Would put Playwright, a browser, a Postgres instance and
  a seeded database into the Docker image build. The build would then be able to fail
  for reasons that have nothing to do with the code being built, and the previews would
  differ between two builds of the same commit.
- **Store them in the media collection or a separate S3 bucket.** Previews become
  environment state: absent in a fresh local checkout, absent in CI, present or stale
  per lane, and drifting from the block set that a given commit actually defines. The
  picker for commit X must show the blocks of commit X, which makes the previews part
  of the source tree, not part of the data.
- **Draw all 45 by hand.** Accurate previews stop being accurate the first time a block's
  design changes, and nobody would redraw them. Deriving from the capture harness means
  a re-run picks up real design changes; hand-drawing is reserved for the blocks where
  a capture cannot be trusted.
- **Skip previews, rely on names.** This was effectively the status quo, and it is what
  US2 exists to fix. It also became less tenable once the description clause was
  retracted (see below) — with no description, the image and the label are the whole of
  the affordance.

## Consequences

- Regenerating is a deliberate, documented step: `npm run seed:showcase`, then
  `npm run visual:capture`, then `npm run block:thumbnails`, then commit the diff.
  `docs/PAYLOAD_DEVELOPMENT.md` carries the procedure; `quickstart.md` carries it for
  this feature.
- A block added without running the generator fails `adminMetadata.int.spec.ts` in CI,
  which stats the committed file rather than requiring a capture run. Adding a block is
  therefore a two-file change (config plus preview), by design.
- The previews are binary files in a public repository and will accumulate history as
  block designs change. At ~3 KB mean this is acceptable; if a future redesign churns
  the whole set repeatedly, revisit by pinning regeneration to release boundaries.
- **One preview is deliberately not a capture.** `video-embed` renders a facade around a
  remote YouTube poster frame: the capture is non-deterministic (it failed outright on
  one run when the thumbnail did not load) and would bake a third party's video still
  into a committed asset in a public repository. It ships as a drawn wireframe.
- The seven rich-text blocks take the same approach at a different size: hand-authored
  20×20 SVGs under `public/block-previews/inline/`, because a screenshot crop is
  illegible at that size and an SVG costs well under a kilobyte.

## The description clause this replaces half of

Spec 011 FR-011 and contract C1 originally required an `admin.description` on every
block. **Payload has no such property** — the `Block` type's `admin` is exactly
`{ components, custom, disableBlockName, group, images, jsx }`, and neither the block
picker nor the Lexical insertion menu renders descriptive text anywhere. A description
would have been a compile error holding prose no editor could read.

The disambiguation intent moved into `labels.singular`, the only editor-visible and
editor-searchable text on a card, enforced by a rule that no label may duplicate or be
a substring of another label in the same picker. That is what makes `Hero (standard
page)`, `Embed (iframe)` and `Testimonial (single)` their current names. Full evidence
is in `specs/011-payload-admin-ux/contracts/admin-metadata.md` C1.

## When to revisit

- Payload adds a rendered block description or a searchable keyword field — then the
  long-form "when to choose this" prose in `docs/BLOCK_LIBRARY.md` §5 has somewhere to
  live in the panel, and the label qualifiers can shorten.
- The committed set approaches the 400 KB budget — raise it deliberately or drop the
  raster width, do not silently exceed it.
- Block designs churn fast enough that preview staleness becomes the common defect —
  then add a CI check that re-captures and diffs, rather than trusting the manual step.
