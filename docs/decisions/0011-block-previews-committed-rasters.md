# 0011. Block picker previews are committed, derived rasters

**Status:** Accepted
**Date:** 2026-08-26

## Context

Payload's block picker shows three things per block: an `admin.group` heading, an `admin.images.thumbnail` image and
`labels.singular`. The image is the only part that shows what a block looks like. The capture harness already renders
every block in isolation, so previews can be derived rather than drawn.

## Options considered

- **Generate at build time** — puts Playwright, a browser and a seeded database into the Docker build, which could then
  fail for reasons unrelated to the code.
- **Store them as media or in S3** — previews become environment state that drifts from the block set a commit defines.
- **Draw them by hand** — stale the first time a design changes.
- **No previews** — names alone did not tell blocks apart.

## Decision

Previews are committed under `public/block-previews/`, generated by an explicit sequence that is never part of a build:
`npm run seed:showcase`, `npm run visual:capture`, then `npm run block:thumbnails`. The source is
`tests/e2e/visual/screenshots/block-previews/<slug>--<variant>.png`; the output is `public/block-previews/<slug>.webp`,
480×320, WebP q78, letterboxed on the block's own background. The 3:2 letterbox matters: Payload draws the thumbnail
into a 3:2 box with `object-fit: cover`, so any other shape is cropped to its middle. The committed set has a 400 KB
budget, enforced by `tests/int/adminMetadata.int.spec.ts`. A block that cannot be captured deterministically may declare
an `.svg` thumbnail in `blockAdmin()` and ship a drawn wireframe. The inline rich-text blocks use 20×20 SVGs under
`public/block-previews/inline/`.

Payload has no block description property, so the disambiguation lives in `labels.singular`: no label may equal, or be a
substring of, another in the same picker (`docs/contracts/admin-metadata.md` C1).

## Consequences

- Adding a block is a two-file change, config plus preview, and CI fails without the preview.
- The previews are binary files in a public repo and accumulate history as designs change (13 files, about 40 KB).
- Regenerating is a deliberate, documented step (`PAYLOAD_DEVELOPMENT.md`).

## Revisit when

Payload renders a block description, the set nears its budget, or stale previews become a common defect (then re-capture
and diff in CI).
